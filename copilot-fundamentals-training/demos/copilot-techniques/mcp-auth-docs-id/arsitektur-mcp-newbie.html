1. Masalah apa yang diselesaikan?

Model AI, yaitu perangkat lunak yang menyusun jawaban dari konteks yang diterimanya, tidak otomatis membaca seluruh folder Anda. Ketika ditanya tentang MyCorp-Auth, ia membutuhkan cara untuk memperoleh informasi yang relevan dari dokumentasi.

MCP (Model Context Protocol) adalah aturan komunikasi agar aplikasi AI dapat memakai fungsi dari program lain. Di sini, aturannya memungkinkan Copilot meminta program Python mencari dokumen. Python adalah bahasa pemrograman yang menjalankan petugas pencari tersebut.

Analogi perpustakaan: Anda adalah pembaca. Copilot adalah asisten di meja layanan. Server authDocs adalah petugas arsip. Folder dokumen adalah rak buku. MCP adalah formulir dan aturan peminjaman informasi yang disepakati bersama.

Mengirim pertanyaan membuat Copilot dapat memilih pencarian. Pencarian menghasilkan kutipan. Kutipan itulah yang digunakan model untuk menyusun jawaban, bukan sekadar mengandalkan pengetahuan umum.

Pembedaan terpenting: authDocs bukan layanan login MyCorp-Auth. Server ini hanya membaca dokumentasi tentang login dan token. Ia tidak menerbitkan token, tidak memeriksa password, dan tidak menghubungi LDAP.

3. Arsitektur yang benar-benar dipakai

Diagram ini mengikuti konfigurasi workspace dan skrip mcp_auth_docs_starter.py. Warna mengelompokkan peran, bukan layanan cloud. Tidak ada Azure, database, atau server HTTP yang diperlukan oleh kode pencarian ini.

Bagian lokal

VS Code menjalankan Python. Python membaca file di komputer Anda, lalu mengirim hasil lewat stdio. Server ini tidak membuka port jaringan.

Bagian model AI

Konfigurasi ini tidak menentukan lokasi atau penyedia model. Copilot dapat mengirim konteks tool ke model sesuai konfigurasi dan kebijakannya. "Server lokal" tidak otomatis berarti seluruh percakapan berjalan offline.

Analogi: petugas arsip dan raknya berada di lokasi Anda. Itu tidak membuktikan bahwa asisten penulis jawaban juga bekerja sepenuhnya tanpa koneksi ke luar.

4. Mengapa konfigurasi ini diperlukan?

Host membutuhkan alamat program yang harus dijalankan. Tanpa petunjuk itu, ia tidak tahu petugas arsip mana yang menyediakan pencarian. Konfigurasi ada di .vscode\mcp.json pada root workspace.

{
  "servers": {
    "authDocs": {
      "type": "stdio",
      "command": "${workspaceFolder}\\copilot-fundamentals-training\\demos\\copilot-techniques\\mcp-auth-docs-id\\.venv\\Scripts\\python.exe",
      "args": [
        "${workspaceFolder}\\copilot-fundamentals-training\\demos\\copilot-techniques\\mcp-auth-docs-id\\mcp_auth_docs_starter.py"
      ]
    }
  }
}
BagianMengapa ada / apa efeknya?
servers.authDocsMendaftarkan satu server dengan nama authDocs agar host dapat mengenalinya.
type: "stdio"Memilih komunikasi proses lokal, bukan alamat website.
commandMenentukan executable Python di .venv; Python tersebut harus sudah tersedia.
argsMemberi Python nama skrip yang harus dijalankan. Tidak ada argumen test, sehingga skrip masuk mode server.
${workspaceFolder}Variabel yang diganti VS Code dengan folder workspace. Pada sesi ini nilainya C:\clients\Organization\demo\fundamental.
\\Penulisan satu karakter backslash di string JSON. Ini bukan dua folder pemisah.
Jika Anda membuka copilot-fundamentals-training langsung sebagai root workspace, awalan path pada konfigurasi ini perlu disesuaikan. Alamat rak harus dihitung dari pintu masuk perpustakaan yang benar.

5. Ikuti perjalanan satu pertanyaan

Client perlu mengenal kemampuan server sebelum memakainya. Setelah itu, model dapat memilih fungsi yang sesuai. Diagram memisahkan tahap membuka koneksi dari tahap menjawab pertanyaan.

  1. Host menjalankan Python. Membaca konfigurasi menghasilkan proses server yang dipakai client. Meja layanan menugaskan petugas arsip dengan perlengkapan yang benar.
  2. Client dan server membuka sesi. Pesan initialize, yaitu permintaan pembuka, dipakai untuk menyepakati versi protokol dan kemampuan. SDK mengurus detail pesan dan notifikasi pembuka. Keduanya menyepakati format formulir.
  3. Client menemukan tool. tools/list meminta daftar fungsi, deskripsi, dan bentuk argumennya. Hasilnya membantu host/model mengenali search_auth_docs. Meja layanan membaca daftar jasa petugas arsip.
  4. Anda mengirim pertanyaan tentang token. Pertanyaan ini menjadi konteks untuk model. Pembaca meminta penjelasan buku tentang token.
  5. Model mengusulkan pemanggilan tool. Sebagai contoh, query="token", limit=8. Host/client mengeksekusinya jika tool tersedia dan izin mengizinkan. tools/call adalah pesan untuk menjalankan fungsi. Asisten mengisi formulir pencarian, penghubung menyerahkannya.
  6. Python mencari paragraf. Membaca Markdown menghasilkan kandidat kutipan, lalu pencocokan memilih yang memuat frasa. Petugas membuka buku dan menandai paragraf yang cocok.
  7. Server mengembalikan hasil terstruktur. Fungsi mengembalikan matches yang berisi nama file dan kutipan. SDK membungkusnya dalam respons MCP. Petugas mengembalikan potongan bacaan beserta nama bukunya.
  8. Copilot menyusun jawaban. Model menggunakan kutipan sebagai konteks untuk merangkum empat langkah. Jika kutipan belum cukup, ia dapat mencari lagi. Asisten menjelaskan bacaan, bukan mengarang isi rak yang belum dibuka.
Pemilihan tool tidak selalu otomatis pada setiap pertanyaan. Mode chat, tool yang diaktifkan, izin, dan keputusan model berpengaruh. Jawaban yang terlihat benar belum membuktikan bahwa pencarian MCP dipanggil.

6. Apa yang dilakukan fungsi pencarian?

Skrip yang dipakai konfigurasi mendaftarkan fungsi melalui @mcp.tool(). Tanda ini adalah dekorator: instruksi Python untuk menjadikan fungsi tersedia sebagai tool. Ini seperti memasukkan layanan pencarian ke katalog jasa arsip.

  1. Rapikan dan validasi input. Spasi di awal/akhir query dibuang. Query kosong ditolak dengan ValueError, yaitu kesalahan nilai masukan. Limit harus 1 sampai 20, default 5. Ini mencegah formulir tanpa kata pencarian atau permintaan kutipan di luar batas.
  2. Temukan rak dokumen. DOCS_DIR dihitung dari lokasi skrip, bukan folder terminal. Jika folder tidak ada, fungsi menghasilkan FileNotFoundError. Petugas membutuhkan rak yang nyata sebelum mencari.
  3. Susuri file. rglob("*.md") mencari file Markdown sampai ke subfolder; daftar diurutkan berdasarkan path. Petugas memeriksa rak dan bagian-bagiannya secara berurutan.
  4. Baca dan pisahkan paragraf. UTF-8 adalah cara mengubah byte menjadi teks. Isi file dipisahkan pada baris kosong dengan pola \n\s*\n. Petugas menilai paragraf, bukan seluruh buku sebagai satu hasil.
  5. Cocokkan frasa literal. casefold() membuat perbandingan tidak peka huruf besar/kecil. Query bukan regex, yaitu bahasa pola pencarian. Jadi TOKEN bisa cocok dengan token, tetapi query tidak dipahami sebagai pertanyaan bahasa alami.
  6. Batasi hasil. Setiap paragraf cocok menambah satu pasangan file dan excerpt. Setelah limit tercapai, fungsi berhenti. Petugas berhenti ketika jumlah kutipan yang diminta sudah terpenuhi.

Contoh bentuk input dan hasil

Contoh berikut menggambarkan argumen tool dan nilai kembalian fungsi, bukan seluruh paket pesan JSON-RPC. Kutipan berasal dari dokumen yang tersedia; urutan aktual mengikuti file yang dipindai.

// Argumen yang dapat dipilih model untuk pertanyaan kita
{"query": "token", "limit": 8}

// Contoh satu hasil; hasil aktual dapat memuat paragraf lain
{
  "matches": [
    {
      "file": "token_flow.md",
      "excerpt": "The following describes how a client obtains and refreshes authentication tokens."
    }
  ]
}

file adalah lokasi relatif terhadap folder dokumentasi. excerpt berarti kutipan paragraf. matches adalah daftar kecocokan; tidak ada kecocokan menghasilkan {"matches": []}, bukan kegagalan server.

Contoh hitungan: limit bukan jumlah buku

Awal panggilan : jumlah kutipan = 0, limit = 8
Paragraf cocok : jumlah kutipan = 1
...
Paragraf cocok : jumlah kutipan = 8 -> berhenti

Delapan kutipan boleh berasal dari satu file yang sama.
Panggilan berikutnya memulai pencarian baru dari awal.

Jika sebuah file awal sudah menghasilkan delapan kecocokan, file berikutnya tidak diperiksa lagi. Jadi pencarian token dengan limit kecil bisa berhenti sebelum mencapai semua isi token_flow.md. Mencapai limit berarti jatah kutipan terpenuhi, bukan semua dokumen relevan sudah dibaca.

Bayangan yang keliruPerilaku kode sebenarnya
Limit 8 berarti delapan dokumen terbaik.Maksimal delapan paragraf cocok, mengikuti urutan path dan paragraf.
Server memahami semua sinonim dan makna pertanyaan.Server mencari frasa literal. Model yang memilih frasa dan menyusun jawaban.
Server sudah mengindeks dan menyimpan semua isi.Kode membaca file saat pencarian; tidak ada indeks vektor atau cache hasil.

Intinya: petugas menandai frasa pada paragraf sesuai urutan rak. Ia bukan penilai otomatis buku terbaik.

7. Apa yang tidak dilakukan server ini?

  • Tidak menjalankan login. Endpoint seperti /login dan /refresh adalah topik di dokumen, bukan route yang dibuat skrip MCP ini.
  • Tidak sama dengan scaffold Flask lama. Skrip di folder induk berisi kerangka aplikasi web Flask dengan endpoint /authdoc yang belum lengkap. Flask adalah framework web Python. Konfigurasi saat ini menunjuk ke skrip FastMCP di folder modul ini, bukan scaffold tersebut.
  • Tidak membutuhkan API key model di Python. API key adalah kredensial akses layanan. Kode ini hanya memakai paket MCP dan file lokal; akses model menjadi urusan host.
  • Tidak menjamin isi dokumen benar. Ada perbedaan rute refresh antar dokumen dan detail yang disamarkan. Model harus menyatakan ketidakpastian, bukan menebak data yang hilang.
  • Tidak membuat sumber informasi otomatis aman. Dokumen bisa salah atau memuat instruksi berbahaya. Perlakukan kutipan sebagai data, bukan perintah yang boleh mengambil alih perilaku asisten.
  • Tidak mengisolasi seluruh izin proses. Fungsi ini hanya membaca folder dokumentasi, tetapi proses Python tetap berjalan dengan izin pengguna yang menjalankannya. Jangan menaruh rahasia di sumber yang akan dikirim ke model.
Analogi: petugas arsip bisa mengambil buku yang salah atau buku dengan isi keliru. Berhasil mendapatkan buku tidak sama dengan menjamin semua pernyataannya benar.

8. Bagaimana membuktikan MCP bekerja?

Ada dua pemeriksaan berbeda. Yang pertama menguji petugas mencari buku. Yang kedua menguji seluruh perjalanan dari meja layanan sampai jawaban.

A. Uji fungsi pencarian, tanpa koneksi MCP

Di VS Code, buka terminal PowerShell pada root workspace C:\clients\Organization\demo\fundamental, lalu jalankan:

& ".\copilot-fundamentals-training\demos\copilot-techniques\mcp-auth-docs-id\.venv\Scripts\python.exe" `
  ".\copilot-fundamentals-training\demos\copilot-techniques\mcp-auth-docs-id\mcp_auth_docs_starter.py" `
  test --query token --limit 2

Argumen test membuat skrip mencetak JSON, lalu selesai. Tanpa test, skrip menjalankan transport MCP. Hasil matches membuktikan Python, paket, dan akses dokumen berjalan, bukan handshake client MCP.

Hasil pemeriksaan saat panduan dibuat: perintah di atas berhasil dan menghasilkan dua kutipan dari misc\support.md. Ini sesuai pencarian rekursif dan limit dua paragraf. Tool MCP juga telah berhasil dipanggil pada sesi chat ini; keberhasilan itu tidak menjamin semua sesi berikutnya otomatis tersambung.

Analogi: meminta petugas mencari langsung membuktikan rak bisa dibaca, tetapi belum membuktikan penghubung di meja layanan bekerja.

B. Uji dari Copilot sampai server

  1. Buka konfigurasi workspace .vscode\mcp.json. Gunakan kontrol Start pada server jika tersedia, atau buka Command Palette dengan Ctrl+Shift+P, cari MCP: List Servers, lalu pilih authDocs. Nama kontrol dapat berbeda menurut versi VS Code.
  2. Jika diminta mempercayai konfigurasi, tinjau command dan script terlebih dahulu. Menyetujui konfigurasi berarti mengizinkan host menjalankan program tersebut.
  3. Di Copilot Chat, gunakan mode yang mendukung tool dan pastikan tool authDocs diaktifkan melalui pemilih tools. Kirim pertanyaan yang sama: "Gunakan search_auth_docs untuk menjelaskan alur token MyCorp-Auth dalam 4 langkah."
  4. Periksa pemanggilan search_auth_docs, yang bisa tampil sebagai authDocs-search_auth_docs. Lihat argumen dan hasilnya. Nama tampilan dapat diberi awalan server oleh host.
  5. Pastikan jawaban mengambil informasi dari kutipan. Jika langkah tidak lengkap, minta pencarian lanjutan dengan frasa yang lebih spesifik; jangan menganggap semua dokumen sudah terbaca.

Hasil yang diharapkan: terlihat panggilan tool, argumen pencarian, hasil kutipan, kemudian jawaban. Itulah bukti alur penuh. Formulir benar-benar sampai ke arsip, hasilnya kembali, dan asisten menjelaskan buku yang diterima.

Anda tidak perlu menjalankan server di terminal secara terpisah sebelum memilih Start. Untuk stdio ini, host menjalankan proses yang terhubung langsung kepadanya; proses manual lain tidak otomatis menjadi server yang dipakai host.

10. Ingat enam kalimat ini

  1. VS Code dan Copilot adalah tempat Anda bertanya.
