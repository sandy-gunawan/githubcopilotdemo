Panduan lengkap
Tentang materi & cara menggunakan panduan

Demo sederhana untuk belajar memberi instruksi yang jelas, memecah tugas, dan memeriksa hasil kerja Copilot.

  • Waktu: sekitar 10-15 menit untuk demo langsung.
  • Alat: VS Code, Copilot Chat, dan Python 3.11 atau lebih baru.
  • Tidak perlu: memasang paket Python tambahan atau membangun Windows Terminal.

Cara memakai panduan: Saat presentasi, ikuti Langkah 0 sampai Langkah 4, lalu sampaikan penutup. Bagian penjelasan kode dan contoh lengkap adalah bahan persiapan pembawa demo.

Untuk versi Markdown, gunakan Ctrl+Shift+V di VS Code. Versi HTML ini bisa dibuka langsung di browser.

01 / Orientasi

Apa tujuan demo ini?

Penting

Tujuan utama: belajar mengarahkan Copilot, bukan sekadar mendapatkan kode.

Kita memberi tugas kecil, memeriksa hasilnya, lalu menentukan langkah berikutnya berdasarkan bukti. Kita tidak langsung menganggap jawaban Copilot pasti benar.

Setelah demo, peserta diharapkan bisa:

  1. Menjelaskan pekerjaan dengan contoh hasil yang diinginkan.
  2. Meminta satu perubahan kecil dan memeriksanya.
  3. Menambahkan kebutuhan baru tanpa mengubah semua hal sekaligus.
  4. Memakai pesan kegagalan nyata untuk memberi arahan berikutnya.

Beberapa istilah yang akan dipakai

Istilah Arti sederhana
Prompt Pesan berisi tugas yang kita berikan kepada Copilot
Fungsi Bagian program yang menerima data, mengerjakan sesuatu, lalu memberikan hasil
Tes Pemeriksaan otomatis dengan contoh dan jawaban yang sudah kita tentukan
Lulus Hasil program sama dengan jawaban yang diharapkan dalam tes
Gagal Hasil program berbeda dari jawaban yang diharapkan dalam tes

Bayangkan seorang petugas toko membaca daftar belanja. Program adalah cara kerjanya. Tes adalah contoh daftar belanja beserta kunci jawabannya.

02 / Skenario

Cerita yang dipakai

Kita meminta petugas toko mencari nama barang yang ditulis lebih dari satu kali. Barang seperti ini disebut duplikat, atau barang yang berulang.

Dalam contoh program, milk berarti susu dan bread berarti roti. Nama ini tetap dipakai agar contoh, kode, dan tes tidak berbeda.

Teks / Contoh hasil
Daftar belanja: ["milk", "bread", "milk"]
Hasil:         ["milk"]

Awalnya, petugas diminta membandingkan tulisan persis seperti yang tertulis. Jadi "Milk" dan "milk" masih dianggap berbeda.

Lalu pelanggan meminta aturan baru:

"Kalau hanya berbeda huruf besar dan kecil, anggap itu barang yang sama. Tetapi tulis hasilnya mengikuti nama yang muncul pertama kali."

Dengan aturan baru, ["Milk", "bread", "milk"] menghasilkan ["Milk"].

Penting: Versi awal tidak salah. Versi awal sudah mengikuti aturan awal. Tes baru akan gagal karena aturan baru memang belum dikerjakan.

03 / Metode

Mengapa tugas perlu dipecah?

Dekomposisi artinya memecah satu pekerjaan menjadi beberapa langkah kecil. Setiap langkah punya hasil yang bisa diperiksa sebelum kita lanjut.

Dalam demo ini, alurnya:

Buat program -> Periksa -> Tambahkan kebutuhan baru -> Ubah program -> Periksa lagi.

Cara ini juga mengenalkan GAR: Generate -> Analyze -> Repair. Dalam bahasa sederhana: Buat -> Periksa -> Perbaiki.

Apa keuntungannya?

  • Arahan lebih jelas. Copilot tahu apa yang harus dikerjakan sekarang.
  • Lebih mudah diperiksa. Kita melihat satu perubahan kecil, bukan banyak hal sekaligus.
  • Lebih mudah mencari penyebab masalah. Salah folder berbeda dengan salah hasil perhitungan.
  • Kemajuan terlihat. Kita punya hasil tes, bukan hanya jawaban "sudah selesai".
  • Perilaku lama ikut dijaga. Tes lama membantu memeriksa apakah perubahan baru merusak hasil sebelumnya.

Ini bukan jaminan program selalu benar atau pekerjaan selalu lebih cepat. Kita tetap harus membaca perubahan dan memeriksa hasilnya.

Ibaratnya: Beri petugas toko satu aturan, periksa jawabannya, baru tambahkan aturan lain.

Mengapa sebelumnya file tidak ditemukan?

Sebelumnya, file dibuat di folder demo1 yang berbeda dari folder pada terminal. Nama foldernya sama, tetapi lokasinya tidak sama.

Untuk perintah python -c, Python mencari file di folder terminal yang sedang aktif dan lokasi pencarian Python lainnya. Python tidak mencari sendiri ke semua folder dalam proyek.

Perhatikan perbedaannya:

Lokasi tujuan file Alamat lengkap tempat file harus dibuat Sebutkan alamat ini agar Copilot tidak memilih folder yang salah

Berpindah folder di terminal tidak otomatis mengganti folder kerja percakapan Copilot. Karena itu, setiap prompt di bawah menyebutkan alamat folder lengkap.

Jika memakai komputer atau folder lain, ganti alamat pada perintah persiapan, keempat prompt, dan perintah bantuan. Nama kedua file Python tetap sama.

Peta perjalanan / Generate - Analyze - Repair

Ringkasan alur demo

Langkah Program pencari barang File tes Hasil yang diharapkan
1 Membandingkan tulisan persis sama Belum dibuat dalam latihan baru Contoh hasilnya sesuai
2 Tidak diubah Tambah tiga tes 3 tes lulus
3 Tetap tidak diubah Tambah satu tes untuk aturan baru 3 tes lulus, 1 tes gagal
4 Ubah agar huruf besar dan kecil dianggap sama Tidak diubah 4 tes lulus

Hubungan kode dan urutan langkah

Bagian contoh kode lengkap memakai label A, B, C, dan D. Itu bukan empat program yang dijalankan terpisah:

  1. Langkah 1 menghasilkan A: fungsi yang mengerjakan pencarian.
  2. Langkah 2 menghasilkan B: tiga tes yang memanggil fungsi dari A.
  3. Langkah 3 menambahkan C ke B: satu tes baru, sementara A tetap sama.
  4. Langkah 4 mengganti A dengan D: fungsi diperbarui, lalu diperiksa dengan tes B dan C yang sama.

Alurnya: A -> diperiksa oleh B -> ditambah pemeriksaan C -> A diganti D.

Saat berpindah langkah, kita memakai hasil langkah sebelumnya. Kita tidak memulai tugas yang tidak berhubungan. Perbedaan pesan tugasnya dijelaskan pada perbandingan Langkah 3 dan 4.

Referensi / Memahami kode

Penjelasan kode dengan bahasa sederhana

Bedanya file program dan file tes

  • duplicates.py mengerjakan pencarian.
  • test_duplicates.py memeriksa hasil pencarian.
  • from duplicates import find_duplicates mengambil fungsi dari file program agar bisa dipakai oleh tes.
  • self.assertEqual(hasil, jawaban) membandingkan hasil nyata dengan jawaban yang diharapkan. Jika berbeda, tes dinyatakan gagal.

Tulisan list[str] berarti daftar berisi teks. Tanda -> list[str] berarti hasil yang diharapkan juga berupa daftar teks. Penanda ini menjelaskan jenis data; Python tidak otomatis memeriksa semua masukan hanya karena penanda itu ada.

Cara kerja versi awal

Program membaca barang satu per satu dan menyimpan tiga catatan:

Nama dalam kode Yang disimpan Gunanya
seen Nama yang sudah pernah dibaca Mengetahui apakah barang muncul lagi
reported Nama yang sudah masuk ke hasil Mencegah nama yang sama ditambahkan berkali-kali
duplicates Daftar hasil yang urut Menyimpan jawaban yang akan diberikan

seen dan reported memakai set, yaitu kumpulan yang tidak menyimpan nilai sama berkali-kali. Urutan jawaban tidak diambil dari set. Program menambahkan hasil ke daftar saat menemukan pengulangan.

Contoh langkah demi langkah:

Urutan baca Barang Tindakan Hasil sementara
1 "milk" Baru pertama kali; ingat namanya []
2 "bread" Baru pertama kali; ingat namanya []
3 "bread" Sudah pernah dibaca; masukkan ke hasil ["bread"]
4 "milk" Sudah pernah dibaca; masukkan ke hasil ["bread", "milk"]
5 "milk" Sudah ada di hasil; jangan tambahkan lagi ["bread", "milk"]

Mengapa bread lebih dulu? Karena bread berulang lebih dulu, walaupun milk muncul paling awal. Yang kita urutkan adalah saat pertama kali berulang, bukan saat pertama kali muncul.

Ibaratnya: Petugas punya catatan barang yang pernah dibaca dan catatan terpisah untuk barang yang sudah dilaporkan.

Apa yang berbeda pada versi akhir?

Versi akhir memakai casefold() untuk membuat teks pembanding yang tidak membedakan huruf besar dan kecil. Teks asli tetap disimpan.

Contohnya, "Milk" dan "milk" sama-sama memakai pembanding "milk". Namun, karena nama pertama adalah "Milk", hasilnya tetap "Milk".

Bagian Versi awal Versi akhir
Cara membandingkan Pakai teks persis seperti yang dibaca Pakai hasil casefold()
Catatan nama seen menyimpan nama yang pernah dibaca first_seen menyimpan pembanding beserta penulisan pertamanya
Pencegah hasil berulang reported menyimpan nama persis reported menyimpan pembanding
Nama yang masuk hasil Nama yang sedang berulang Nama asli yang muncul pertama kali

first_seen memakai dictionary, yaitu catatan pasangan. Misalnya, first_seen["milk"] = "Milk" berarti "untuk pembanding milk, penulisan pertamanya adalah Milk".

Kedua versi tidak menghapus spasi. Karena itu " milk" dan "milk" tetap dianggap berbeda. Daftar kosong juga tetap menghasilkan [].

Ibaratnya: Petugas menyamakan cara membandingkan nama, tetapi tetap menyalin penulisan pertama dari daftar pelanggan.

Contoh A: versi awal duplicates.py

Dipakai pada Langkah 1. Inilah fungsi yang kemudian diperiksa oleh Contoh B.

Contoh kode / Python
def find_duplicates(items: list[str]) -> list[str]:
    seen: set[str] = set()
    reported: set[str] = set()
    duplicates: list[str] = []

    for item in items:
        if item in seen and item not in reported:
            duplicates.append(item)
            reported.add(item)
        seen.add(item)

    return duplicates

Contoh B: tiga tes awal di test_duplicates.py

Dipakai pada Langkah 2. Baris from duplicates import find_duplicates menghubungkan file tes ini dengan fungsi pada Contoh A.

Contoh kode / Python
import unittest

from duplicates import find_duplicates


class DuplicateTests(unittest.TestCase):
    def test_reports_duplicates_once_in_repeat_order(self):
        self.assertEqual(
            find_duplicates(["milk", "bread", "bread", "milk", "milk"]),
            ["bread", "milk"],
        )

    def test_returns_empty_for_unique_items(self):
        self.assertEqual(find_duplicates(["milk", "bread"]), [])

    def test_returns_empty_for_empty_input(self):
        self.assertEqual(find_duplicates([]), [])


if __name__ == "__main__":
    unittest.main()

Dengan Contoh A dan B, perintah python -m unittest -v test_duplicates menghasilkan tiga tes lulus.

Contoh D: versi akhir duplicates.py

Dipakai pada Langkah 4 untuk mengganti Contoh A di file yang sama. Contoh B beserta tambahan C tetap dipakai tanpa perubahan.

Contoh kode / Python
def find_duplicates(items: list[str]) -> list[str]:
    first_seen: dict[str, str] = {}
    reported: set[str] = set()
    duplicates: list[str] = []
    for item in items:
        key = item.casefold()
        if key not in first_seen:
            first_seen[key] = item
        elif key not in reported:
            duplicates.append(first_seen[key])
            reported.add(key)
    return duplicates

Dengan Contoh D dan keempat tes, semua tes lulus. File tes tidak perlu diubah lagi setelah Langkah 3.

Bantuan / Troubleshooting

Bantuan jika demo tidak sesuai

File tidak ditemukan

Pesan ModuleNotFoundError: No module named 'duplicates' biasanya berarti file program tidak ada di folder pencarian Python atau namanya tidak sesuai.

Ulangi Langkah 0, lalu jalankan:

Terminal / PowerShell
Set-Location -LiteralPath "C:\clients\Organization\demo\fundamental\terminal\tools\copilot-prompting-demo\demo1"
Get-Location
Get-ChildItem -Name
python -c "import duplicates; print(duplicates.__file__)"

Perintah terakhir harus menunjukkan alamat file program di folder demo1 yang benar. Jangan mengubah tes untuk mengatasi kesalahan lokasi.

Ibaratnya: Petugas tidak bisa membaca daftar yang ditinggal di meja lain.

Tes tidak berjalan

Jika python tidak dikenali, gunakan perintah Python yang sudah berhasil pada Langkah 0.

Jika muncul Ran 0 tests, periksa nama fungsi tes: harus dimulai dengan test_ dan berada dalam kelas unittest.TestCase, seperti pada Langkah 2.

Kesalahan penulisan kode atau file yang tidak ditemukan bukan kegagalan yang ingin kita tunjukkan pada Langkah 3.

Ibaratnya: Kunci jawaban yang belum bisa dibaca berbeda dengan jawaban petugas yang salah.

Tes baru langsung lulus

Mungkin program sudah menyamakan huruf besar dan kecil, atau ikut diubah saat tes baru ditambahkan. Periksa kembali Langkah 1 dan Contoh A.

Jangan menyisipkan kesalahan agar demo terlihat gagal. Untuk mengulang, gunakan contoh awal yang dijelaskan secara terbuka di folder latihan baru.

Ibaratnya: Jika petugas sudah mengikuti aturan baru, tidak ada aturan yang perlu diperbaiki.

Jangan membuat kegagalan palsu

@unittest.expectedFailure hanya memberi label bahwa tes diharapkan gagal. Penanda itu tidak membuat jawaban program menjadi salah. Jika tes justru lulus, muncul UNEXPECTED SUCCESS.

Pada Langkah 3, gunakan tes biasa. Jangan melewati tes, mengganti hasil dengan hasil buatan, atau memberi label harus gagal. Inilah alasan prompt melarang skip, mock, expectedFailure, dan xfail.

Ibaratnya: Menempelkan label "harus salah" bukan bukti bahwa jawaban petugas salah.

Tes diubah agar lulus

Jika jawaban yang diharapkan diubah menjadi [], aturan baru justru dihapus, bukan dikerjakan. Pada Langkah 4, pertahankan keempat tes dan ubah programnya saja.

Jika hasilnya ["milk"], bukan ["Milk"], program belum menjaga penulisan pertama. Lihat pemakaian first_seen pada Contoh D.

Ibaratnya: Perbaiki cara kerja petugas, bukan kunci jawabannya.
